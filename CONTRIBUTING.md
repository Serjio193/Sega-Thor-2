# Contributing

Read `AGENTS.md` and `AI_DEVELOPMENT_CONTRACT.md` before changing the repository.

Keep reverse-engineering notes, legal-safe clean-room/native code, tests, tooling, hashes/manifests, and derived metadata in GitHub. Do not commit commercial disc images, extracted retail binaries/assets, BIOS files, save states, RAM dumps, raw copyrighted traces, proprietary/leaked SDK material, or other private/commercial game data.

Prefer small, single-purpose changes with tests/evidence. When translating or classifying a routine/block/module, preserve the original revision, address/range, module/disc provenance, observed side effects, confidence/trust level, and verification status.

Semantic production C++ for a concrete slice requires `CURRENT SLICE UNDERSTANDING CONFIDENCE >= 90%`. Verified mechanically generated machine-equivalent code is the documented exception; it does not grant semantic confidence.

Before proposing a PR, follow `docs/DEVELOPMENT_RULES.md`. PR descriptions should state goal, exact scope, evidence, tests/verification, documentation updates, known unknowns, and exact next step.
